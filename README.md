# Markdown Preview(単独 HTML 版)

Chrome で開くだけで動く、Markdown のエディタ兼プレビューです。VSCode + Markdown Preview Enhanced(MPE)の代わりに使うことを想定しています。

- **HTML 1 ファイルだけで動きます。** Node.js・サーバ・インストールは不要で、閉域(オフライン)の PC でも使えます
- **HTML 出力は CSS を埋め込みます。** 出力した HTML を配布しても見た目が崩れません。画像まで埋め込んだ 1 ファイル出力もできます
- **画像に赤枠・矢印・吹き出しを直接書き込めます。** 貼り付けた画像を後から何度でも編集できます(drawio は不要です)
- **style.css を保存するとすぐにプレビューへ反映されます。** キャッシュの問題は起きません

## 動作要件

- Windows 10 以降の **Google Chrome 122 以降**(ファイルの読み書きに File System Access API を使います)
- md ファイルがあるフォルダ(ローカルでも共有フォルダでもよい)への読み書き権限

## 導入

1. `dist/mdpreview.html` を好きな場所に置きます(デスクトップや共有フォルダなど)
2. エクスプローラで右クリック →「プログラムから開く」→ **Google Chrome** で開きます
   (Chrome が既定のブラウザならダブルクリックで開けます)
3. ブックマークしておくと次から開きやすくなります

## 使い方

### ワークスペース(フォルダ)を選ぶ

1. 起動画面の「フォルダを選ぶ」で、md ファイルが入っているフォルダを選びます
2. Chrome に「このサイトにファイルの編集を許可しますか?」と聞かれたら **「編集を許可」** を選びます

2 回目以降は、起動画面の「前回のフォルダを再許可」(または最近使ったフォルダの一覧)を押すだけで再開できます。
Chrome の仕様上、ブラウザを開き直すたびにこの再許可のクリックが 1 回必要です。

> [!NOTE]
> 開けるのは、選んだフォルダ(ワークスペース)の中のファイルだけです。
> `@import "../共通/xx.md"` のように上の階層を参照している場合は、上の階層のフォルダをワークスペースに選んでください。

### 編集と保存

- 左のツリーで md を選ぶと、中央のエディタと右のプレビューに表示されます
- **Ctrl+S** で保存します。未保存のときはファイル名に「●」が付きます
- ツールバーで「エディタのみ / 両方 / プレビューのみ」を切り替えられます。エディタとプレビューの境目はドラッグで幅を変えられます
- エディタとプレビューのスクロール位置は連動します
- URL の末尾に `#file=docs%2Fa.md` のようにファイルを指定してブックマークすると、そのファイルを直接開けます

### ファイルとフォルダの操作

- 入口は2つあります。**サイドバー上部のボタン**(「＋ md」「＋ フォルダ」「⟳」= ツリーの再読込)と、**ツリーの右クリックメニュー**です
  - md の行を右クリック: 名前の変更 / 削除
  - フォルダの行を右クリック: 新規 md / 新規フォルダ / 名前の変更 / 削除(そのフォルダの中に作られます)
  - ツリーの余白(ルート)を右クリック: 新規 md / 新規フォルダ
  - ツリーの行を選んだ状態で **F2** = 名前の変更、**Delete** = 削除
- 新規作成の作成先は、今開いている md のフォルダ(開いていなければルート)が初期値です。入力欄に `sub/memo` のように
  フォルダ付きで打つと、途中のフォルダも無ければまとめて作られます。新規 md の中身は空(0 バイト)です
- 名前の決まり: Windows でも使えるように、`\ / : * ? " < > |` や制御文字、`.` で終わる名前、`CON` `PRN` `COM1` などの
  Windows の予約名は使えません。`.` で始まる名前も使えません(ツリーに表示されなくなるため)。同名のファイル・フォルダ
  (**大文字小文字を区別しません**。Windows と同じ)が既にある場合も使えません。md は拡張子(`.md` / `.markdown`)を
  付けなくても自動で `.md` が付きます
- **削除はごみ箱に入らず完全に削除されます(元に戻せません)。** フォルダを削除すると中身も丸ごと削除されます
  (削除前に md・その他のファイル・フォルダの件数を確認できます)。開いている md(またはそれを含むフォルダ)を
  削除すると、そのファイルは閉じます
- 名前を変更しても、**他の md からのリンク・`@import`・画像フォルダ(`images/<md名>/`)の参照先は書き換えません。**
  画像の参照パスは変わらないので、md の名前を変えても既存の画像はそのまま表示されます(リンク切れが心配な場合は、
  リンクする側も手動で直してください)
- **フォルダの名前の変更は、コピーしてから元のフォルダを削除する方式で行われます**(Chrome がフォルダの名前を
  直接変更する API に対応していないため)。フォルダの中身が多いと時間がかかり、コピー後は中のファイルの更新日時が
  新しくなります(内容は変わりません)。ファイル1つだけの名前の変更は、ほとんどの場合すぐに終わります

### 他の人の変更や、ほかのエディタでの変更

- 開いているファイルが外部で変更されると、未保存の変更がなければ自動で取り込みます。未保存の変更がある場合は、画面上部の通知バーで知らせます
- 保存しようとしたときに、ほかの人が先に同じファイルを更新していた場合は、「上書き保存 / 破棄して再読込 / キャンセル」を選べます

## 対応している記法

| 記法 | 内容 |
|---|---|
| 標準の Markdown | 見出し・リスト・表・コードブロック(色付け)・引用・脚注・タスクリスト(`- [ ]`) |
| 改行 | 段落の中で 1 回改行すると、そのまま改行して表示します(MPE と同じ)。段落を分けるときは空行を入れます |
| mermaid | ```` ```mermaid ```` のコードブロックを図として表示します |
| `@import "x.md"` | 別の md を取り込みます。`<!-- @import "x.md" -->` の形式も使えます。取り込んだ md の中の画像やリンクのパスは自動で調整されます |
| `[TOC]` | 表示するときだけ、その位置に目次を展開します(md 自体は書き換えません) |
| `<!-- @import "[TOC]" {cmd="toc" depthFrom=1 depthTo=6 orderedList=false} -->` | MPE と同じ方式の目次です。**保存するたびに** md 本文の目次を自動で更新します |
| `> [!NOTE]` など | アラート(NOTE / TIP / IMPORTANT / WARNING / CAUTION / LINK / MEMO / CHECK / QUESTION の 9 種類)。詳しくは [アラート](#アラート) を参照してください |
| `==強調==` | 蛍光ペン(黄色)。`{.mark-text}` を付けると黄色 + 赤枠になります。詳しくは [蛍光ペン](#蛍光ペン) を参照してください |
| ```` ```mark ```` | マーカー付きテキスト枠。枠内の `==強調==` は黄色 + 赤枠になります。詳しくは [蛍光ペン](#蛍光ペン) を参照してください |
| `{#id .class}` | 見出しなどに id やクラスを付けます。見出しに `{ignore=true}` を付けると目次に載りません |
| `![](a.png){width="300px"}` | 画像の表示サイズを指定します。`<img src="a.png" width="300">` も使えます |
| `![](a.png){.no-border}` | 画像の枠線を消します(画像には既定で 1px の枠線が付きます) |
| 表の後に空行を挟んで `{.full}` | 直前の表を本文幅いっぱいに広げます(表の直後の行ではなく、空行を挟む必要があります) |
| YAML front matter | 表示しません |

見出しの id(リンク先)は MPE と同じ規則で作ります。MPE で書いた md 内の `[概要へ](#概要)` のようなリンクは、そのまま機能します。

**非対応**: PlantUML、MPE の code chunk(コードの実行)、md 以外のファイルの `@import`、数式(KaTeX)

## アラート

注意書きや補足を、アイコン付きの角丸の枠で囲んで表示します。**標準は GitHub 方式**(`> [!NOTE]`)です。9 種類あり、使いどころの目安は次のとおりです。

| 種類 | 記法 | 使いどころ |
|---|---|---|
| NOTE | `> [!NOTE]` | 読み手に知っておいてほしい補足 |
| TIP | `> [!TIP]` | 知っていると便利な助言(読まなくても作業はできる) |
| IMPORTANT | `> [!IMPORTANT]` | 必ず知っておくべき情報 |
| WARNING | `> [!WARNING]` | 注意しないと問題が起きること |
| CAUTION | `> [!CAUTION]` | 結果が深刻、または取り返しがつかない操作 |
| LINK | `> [!LINK]` | 関連資料・参照先 |
| MEMO | `> [!MEMO]` | 書き手の備考・作業メモ(本文の理解には不要) |
| CHECK | `> [!CHECK]` | 読み手が行う確認作業(作業後の確認ポイントなど) |
| QUESTION | `> [!QUESTION]` | 未解決の論点・要確認事項(完成版では解決して削除する。`[!QUESTION]` で検索すると残件を洗い出せます) |

### 書き方

標準は GitHub 方式です。引用(`>`)の 1 行目に `[!種類]` を書きます。

```markdown
> [!NOTE]
> 読み手に知っておいてほしい補足です。
```

マーカーと同じ行に文字を書くと、その文字がタイトルになります(GitHub 本来の仕様には無い、この実装独自の拡張です)。

```markdown
> [!WARNING] 注意事項
> 作業前に必ずバックアップを取ってください。
```

社内資料に Qiita 方式(`:::note info` 〜 `:::`)が混在している場合もそのまま使えます。見た目は GitHub 方式と同じになります。

```markdown
:::note info
Qiita 方式でも同じ見た目になります。
:::
```

`note` を省略して、種類名を `:::` の直後に直接書く省略形にも対応しています(`:::memo` / `:::check` / `:::question` / `:::info` / `:::warn` / `:::alert` / `:::tip` / `:::link` など)。種類語の後ろに文字を書くとタイトルになります。

```markdown
:::memo
作業メモです。完成版では削除してください。
:::
```

Qiita 方式を入れ子にするときは、外側のコロンを内側より多くしてください(同じ数だと、内側の閉じ `:::` で外側も閉じてしまいます)。

```markdown
::::note warn
外側のアラートです。

:::memo
内側のアラートです。
:::
::::
```

### タイトルの変更・非表示

タイトルの文字はツールバーの ⚙(設定)から種類ごとに変更できます。**入力欄を空欄にすると、タイトル文字を出さずアイコンだけを本文の左側に表示します**(Qiita の note のような見た目になります)。md 側で `> [!NOTE] 見出し` のように明示的にタイトルを書いた場合は、設定が空欄でもその文字が優先されます。各入力欄の「既定に戻す」ボタンで既定のタイトルに戻せます。

### 色の変更

色は種類ごとに CSS 変数(`--mdp-alert-color` / `--mdp-alert-border` / `--mdp-alert-bg`)にまとめているので、style.css で変数だけ上書きすれば色を変えられます。例えば warning の色を変えたいときは次のように書きます。

```css
.markdown-alert-warning {
  --mdp-alert-color: #b45309;
  --mdp-alert-border: #f2c879;
  --mdp-alert-bg: #fff8ea;
}
```

## 蛍光ペン

段落・見出し・リスト・表のセルなど、本文のどこでも `==` で囲むとハイライト表示になります。3 通りの書き方があります。

1. `==強調==` は黄色のハイライトだけになります(VSCode Markdown Preview Enhanced と同じ見た目です)
2. `==強調=={.mark-text}` は黄色 + 赤枠になります(指摘・注意喚起用)
3. ```` ```mark ```` のコードブロックは、複数行にまたがる範囲をまとめて枠(グレーの背景)で囲みます。中は Markdown として解釈されず(空白・改行・字下げはそのまま表示されます)、枠内の `==強調==` の部分だけ黄色 + 赤枠になります

```markdown
段落中の ==強調== と ==強調=={.mark-text} です。
```

````markdown
```mark
ここは普通の文字 ==ここを強調== 続き
  字下げや改行はそのまま表示されます
```
````

`==` をそのまま文字として書きたいときは、本文でもマーカー付きテキスト枠の中でも `\==` と書いてください。対応しない `==`(閉じが無い、または中身が空の `====`)はそのまま文字として表示されます。

既存資料の生 HTML `<pre class="mark-box">…<span class="mark-text">…</span>…</pre>` をそのまま貼り付けても、同じ見た目で表示されます。

色は CSS 変数(`--mdp-mark-bg` / `--mdp-mark-border` / `--mdp-markbox-bg` / `--mdp-markbox-border`)にまとめているので、style.css で変数だけ上書きすれば変えられます。この見た目はアラートと同じく、設定の「標準 CSS を使う」のオン/オフに関係なく常に適用されます。

```css
.crossnote.markdown-preview {
  --mdp-mark-bg: #fff59d;
  --mdp-mark-border: #e53935;
  --mdp-markbox-bg: #f5f5f5;
  --mdp-markbox-border: #e0e0e0;
}
```

## 表の整形

GFM の表(パイプ区切り)の列幅を、全角文字の幅も考慮して自動で揃え直せます。Excel からのタブ区切りテキストの貼り付けを Markdown の表に変換する機能は [画像の貼り付けと注釈](#画像の貼り付けと注釈) の節を参照してください。

- ツールバーの **「表を整形」** ボタン、または **Alt+Shift+F**(VS Code の「ドキュメントのフォーマット」と同じキー)で、文書中のすべての表をまとめて整形します
- 全角文字(ひらがな・漢字など)は表示幅 2、半角の英数字は表示幅 1 として列幅を揃えます
- 区切り行の配置指定(`:--` 左寄せ / `--:` 右寄せ / `:-:` 中央)はそのまま保たれます
- フェンスコードブロック(```` ``` ```` / `~~~`)の中と、引用(`>`)の中の表は対象外です
- 整形が必要な表が無い場合は「整形が必要な表はありません」と表示されます。**保存時に自動で整形することはありません**

## 画像の貼り付けと注釈

### 貼り付け・ドロップ

エディタにクリップボードの画像を貼り付ける(Ctrl+V)か、画像ファイルをドロップすると、MPE と同じく md と同じフォルダの `images/<md名>/image-<連番>.png` にファイルとして保存し、`![](images/<md名>/image-1.png)` をカーソル位置に挿入します(ドロップしたファイルは元の拡張子のまま)。連番はフォルダ内の既存の番号の続きから振ります。md に画像を base64 で埋め込むことはしません(base64 で埋め込むのは [HTML 出力](#html-出力) の「1ファイル出力」のときだけです)。

保存中はカーソル位置に「⏳ 画像を保存中…」が表示され、保存が終わると参照に差し替わります。保存中にもう一度画像を貼り付け・ドロップしても受け付けません(「前の画像を保存中です。保存が終わってから貼り付けてください」)。保存の途中で別の md に切り替えた場合は、画像は保存しますが開いている本文には参照を挿入しません(状態表示に保存したパスを案内します)。

Excel のセルのコピーのように、クリップボードに画像とテキストの両方がある場合は、貼り付け方法を選ぶ小さなメニューが出ます。**画像で貼り付け(Enter / 1)/ テキストで貼り付け(2)/ 表(Markdown)で貼り付け(3、タブ区切りのときだけ)** から選べます(Esc・メニュー外のクリックで取り消し)。**Ctrl+Shift+V**(ブラウザの「書式なしで貼り付け」)ならメニューを出さずテキストだけを貼り付けます。

**draw.io の図を貼るとき:** draw.io の通常のコピー(Ctrl+C)は画像ではなく図形データをコピーするため、貼り付けても挿入せず、下の状態表示に案内を出します。次のどちらかで貼ってください。

- draw.io の **編集 > 画像としてコピー(Edit > Copy as Image、Ctrl+Alt+X)** でコピーしてから貼り付ける(普通の PNG として保存されます。draw.io で開き直すための図形データは入りません)
- draw.io の File > Export as > PNG で **Include a copy of my diagram** をオンにして書き出し、そのファイルをドロップする(`xxx.drawio.png` は `image-<連番>.drawio.png` として保存するので、draw.io で開き直せます)

VS Code の draw.io 拡張では Copy as Image が使えないことがあります。その場合は書き出してドロップしてください。

### 注釈(赤枠・矢印・吹き出し)

プレビューの画像にマウスを乗せると、右上に **「✎ 編集」** ボタンが出ます。押すと注釈エディタが開きます。

| ツール | 操作 |
|---|---|
| 選択(V) | クリックで選択、ドラッグで移動、角のハンドルで大きさを変更、Delete で削除 |
| 赤枠(R) | ドラッグで枠を描きます |
| 矢印(A) | ドラッグで描きます。端を枠の上で離すと枠につながり、枠を動かすと矢印も付いてきます |
| 吹き出し(T) | しっぽの先端から吹き出しの位置へドラッグします(クリックだけでも作れます)。作るとすぐに文字の入力欄が開きます。後から文字を直すときは、ダブルクリックするか、選択して Enter か F2 を押します |
| 切り抜き(C) | 残したい範囲をドラッグします。「切り抜き解除」で元に戻せます |
| 出力倍率 | 100% / 75% / 50% / 任意の値。保存する PNG を実際に縮小します(高解像度の画面のスクリーンショットに便利) |

- 色と線の太さはツールバーで選べます。Ctrl+Z で元に戻す、Ctrl+Y でやり直しです
- 保存すると、注釈を焼き込んだ PNG で元のファイルを上書きします。PNG の中に元の画像と図形の情報も入れておくので、**もう一度「✎ 編集」を押すと、図形を動かしたり消したりできます**(その分、ファイルサイズは元の画像ぶん大きくなります)
- JPEG などの PNG 以外の画像を編集すると、同じフォルダに `.png` を作り、md 内の参照を書き換えます(未保存の状態になるので Ctrl+S で保存してください)
- 表示の大きさだけ変えたいときは、md 側で `{width="300px"}` を指定してください

### 複数の画像をまとめる

注釈エディタは複数の画像を1枚のキャンバスにまとめられます(draw.io のように自由に配置できます)。

- **追加**: ツールバーの「画像を追加」、エディタを開いた状態での Ctrl+V、キャンバスへのドロップのいずれかで追加できます。複数のファイルを一度に選んだりドロップしたりしても重ならず、横に順番に並びます
- **画像が2枚以上あるとき**だけ、選択ツール(V)で画像自体を選べます(1枚だけのときは、移動しても出力が変わらないため今までどおり選択できません)
  - クリックで選択、ドラッグで移動(うっかりずらし防止のため、わずかな移動では動きません)
  - 四隅のハンドルで拡大縮小(縦横比は保たれます)
  - Delete で削除(最後の1枚は消せません)。元に戻す(Ctrl+Z)で復活します
  - ツールバーの「最前面へ」「最背面へ」で画像同士の重なり順を変えられます(注釈は常に画像より手前に描かれます)
- **切り抜き**は画像ごとに行います。選択ツールで画像を選んでから切り抜きツール(C)に切り替えると、その画像がそのまま切り抜きの対象になります。画像が2枚以上あるときに未選択のまま切り抜きツールに切り替えた場合は、切り抜きたい画像を先にクリックしてください
- **出力範囲**は、すべての画像(切り抜き後)とすべての注釈を囲む最小の範囲に自動的に決まります。画像の無い部分は白で塗られ、エディタ上には点線で表示されます

### 表示の操作(パン・ズーム)

キャンバスは無限に広く、次の操作で表示位置・倍率を変えられます(内容自体の位置は変わりません)。

- ホイール: 上下にパン、Shift+ホイール: 左右にパン、Ctrl+ホイール: カーソル位置を中心にズーム、中ボタンドラッグ: パン
- 「全体表示」ボタン: 内容全体が収まる倍率(最大100%)で中央に表示します。エディタを開いた直後もこの状態です

### 注意

- 元の画像はすべて PNG に埋め込んで保存するため、画像の枚数が多いほどファイルサイズが大きくなります
- 保存した PNG を以前のバージョンのアプリ(このキャンバス機能より前のバージョン)で開くと、焼き込み済みの1枚の画像として開きます(壊れませんが、注釈の再編集はできません)

## HTML 出力

ツールバーの「HTML 出力」から選びます。出力先は md と同じフォルダです。

| 種類 | ファイル名 | 用途 |
|---|---|---|
| 通常 | `<md名>.html` | 共有フォルダのパスで共有するとき。画像は相対パスで参照するので、`images/` フォルダと一緒に置いてください |
| 1ファイル | `<md名>.standalone.html` | メールやチャットで送るとき。画像も HTML の中に埋め込みます |

- どちらも CSS(既定のテーマ + style.css)は HTML の中に書き込みます。mermaid の図は描画済みの SVG として入るので、JavaScript は含みません
- PDF にしたいときは、出力した HTML を Chrome で開いて Ctrl+P で「PDF に保存」を選んでください

## 設定

ツールバーの ⚙ から変更します。設定はこの PC の Chrome に保存されます。

| 項目 | 内容 |
|---|---|
| 外部での変更を自動検知する / 検知間隔(秒) | 外部での変更を確認するかどうかと、その間隔(既定 2 秒)。オフにしても、ウィンドウに戻ったときには確認します |
| CSS のパス(ルート相対) | プレビューと HTML 出力に使う CSS の場所(ワークスペースからの相対パス。既定は `style.css`) |
| 標準 CSS を使う | 社内資料向けの標準 CSS(既定オン)を使うかどうか。オフにすると CSS のパスのファイルだけを使います(アラート・蛍光ペン・マーカー付きテキスト枠の見た目は常に適用されます) |
| 標準 CSS を書き出す | 標準 CSS をワークスペース直下に `standard.css` として書き出します。見た目を変えたいときの元ファイルにしてください |
| h2 以降の見出しに連番を付ける | 見出しに `1.` / `1-1.` / `1-1-1.` のような連番を付けるかどうか(既定オフ)。詳しくは [見出しの連番と字下げ](#見出しの連番と字下げ) を参照してください |
| 番号を付ける深さ | 連番を付ける最も深い見出し(h2 のみ 〜 h2〜h6。既定は h2〜h6) |
| 見出しの階層ごとに字下げする | 見出しとその本文を、階層が深いほど字下げするかどうか(既定オフ) |
| アラートのタイトル | `> [!NOTE]` などで表示するタイトル(既定は Note / Tip / Important / Warning / Caution / Link / Memo / Check / Question)。空欄にするとアイコンだけになります。詳しくは [アラート](#アラート) を参照してください |

### 標準 CSS(社内資料向け)

既定では、見出し(アクセント色の下線・帯・縦線)と表(見出し行の色付け・縞模様・印刷時の見出し行の繰り返し)を中心に整えた「標準 CSS」が適用されます。本文は薄いグレーの背景の上の白い表示エリア(最大幅 1200px)に表示します(印刷時は背景と枠を出さず、紙いっぱいに使います)。見た目を変えたいときは、標準 CSS を直接編集するのではなく、次の手順で置き換えます。

1. 設定の「標準 CSS を書き出す」を押すと、ワークスペース直下に `standard.css` ができます
2. `standard.css` を好きなように編集します
3. 設定の「CSS のパス」を `standard.css` に変更します
4. 設定の「標準 CSS を使う」をオフにします(アラート・蛍光ペン・マーカー付きテキスト枠の見た目は常に適用されるので、この手順では変わりません)

色やフォントだけを変えたい場合は、書き出さずに `style.css` 側で次の CSS 変数を上書きするだけでも変えられます(標準 CSS はオンのまま)。

| 変数 | 内容 |
|---|---|
| `--mdp-font` / `--mdp-font-mono` | 本文のフォント / コード等の等幅フォント |
| `--mdp-text` / `--mdp-muted` | 本文の文字色 / 補足的な文字色(h6・脚注など) |
| `--mdp-accent` / `--mdp-accent-soft` / `--mdp-accent-line` | 見出しなどのアクセント色(紺) / h2 の帯・表の見出し行の背景 / h3 の縦線・表の見出し行の下罫線 |
| `--mdp-border` / `--mdp-border-light` | 表の罫線 / 水平線・コードの枠線 |
| `--mdp-link` | リンクの色 |
| `--mdp-code-bg` | インラインコード・コードブロックの背景 |
| `--mdp-zebra` | 表の縞模様(偶数行)の背景 |
| `--mdp-content-width` | 表示エリア(白い部分)の最大幅(既定 1200px) |
| `--mdp-paper-bg` / `--mdp-paper-border` | 表示エリアの背景 / 枠線 |
| `--mdp-page-bg` | 表示エリアの外側の背景(薄いグレー)。これだけは `:root` に書きます |

例えば、アクセント色を紺から緑に変えたいときは `style.css` に次のように書きます。

```css
.crossnote.markdown-preview {
  --mdp-accent: #1b6e3c;
  --mdp-accent-soft: #eaf5ee;
  --mdp-accent-line: #7fb996;
}
```

表示エリアの幅や外側の背景を変えたいときは、次のように書きます。

```css
.crossnote.markdown-preview {
  --mdp-content-width: 1200px;
}
:root {
  --mdp-page-bg: #ffffff; /* 外側も白にする */
}
```

表を本文幅いっぱいに広げたいときは、表の後に**空行を挟んで** `{.full}` と書きます(表の直後の行に続けて書くと、表の続きの行として解釈されてしまいます)。

```markdown
| 項目 | 内容 |
|---|---|
| a | 1 |

{.full}
```

画像には既定で 1px の枠線が付きます。枠線を消したいとき(透過 PNG やアイコンなど)は `{.no-border}` を付けます。

```markdown
![説明](a.png){.no-border}
```

### 見出しの連番と字下げ

設定(⚙)の「h2 以降の見出しに連番を付ける」「見出しの階層ごとに字下げする」で、それぞれ個別にオン/オフできます(既定はどちらもオフ)。md 本文(見出しの文字や `#` の数)は書き換えません。

- 番号は `1.`(h2)/ `1-1.`(h3)/ `1-1-1.`(h4)のように、区切りを `-` にして階層を表します。h1 には付けません
- 「番号を付ける深さ」で、番号を付ける最も深い見出し(h2 のみ 〜 h2〜h6)を選べます。それより深い見出しには付きません
- 手書きの番号(`## 1. はじめに` など)がある資料では番号が二重になります。番号を付けたくない見出しは `## 改訂履歴 {.nonum}` のように書いてください。その見出し配下(次に同じかより浅い見出しが来るまでの、より深い見出し)にも番号は付きません
- `[TOC]` と、保存時に md へ書き込む MPE 方式の目次(`<!-- @import "[TOC]" ... -->`)のどちらにも同じ番号が付きます(本文の段落中の普通のリンクには付きません)
- 字下げは見出しと本文の両方を、階層が深いほど下げます(h2 は字下げなし、h2 の本文と h3 は 1 段、h3 の本文は 2 段…)。1 段の幅は CSS 変数 `--mdp-indent-step`(既定 1.5em)で、style.css で上書きすれば変えられます
- どちらの設定もこの PC の Chrome に保存され、開いている・開くすべての md に効きます。HTML 出力には出力した時点の設定が反映されます

### style.css(MPE の style.less からの移行)

- ワークスペース直下に `style.css` を置くと、プレビューと HTML 出力に反映されます
- 本文は MPE と同じ `<div class="crossnote markdown-preview">` で囲んでいるので、`.markdown-preview` を使ったセレクタはそのまま使えます
- less の入れ子や変数は使えません。通常の CSS に書き直してください
- アラートは GitHub と同じ HTML(`div.markdown-alert.markdown-alert-note` と、アイコン付きの `p.markdown-alert-title`)で出力します(`> [!NOTE]` と `:::note info` のどちらも同じ HTML になります)。今の parser.js が別のクラス名を出力している場合は、style.css のセレクタをこちらに合わせてください。色を上書きする方法は [アラート](#アラート) を参照してください

## 困ったときは

| 症状 | 対処 |
|---|---|
| 「File System Access API に対応していません」と出る | Google Chrome 122 以降で開いてください |
| 起動するたびに再許可を求められる | Chrome の仕様です。「前回のフォルダを再許可」を押してください |
| 画像が表示されない | 画像がワークスペースの外にないか、パスが正しいかを確認してください |
| `@import "…": 見つかりません` などと表示される | 取り込み先のパスを確認してください。ワークスペースの外は参照できません |
| 保存に失敗する | 共有フォルダにアクセスできるか(VPN・権限)を確認してください。共有フォルダで起きる一時的なエラーは自動で再試行します |
| 画面が崩れた・動かない | Ctrl+F5 で開き直してください。未保存の変更は失われるので、先に保存してください |

## 開発者向け

配布物は `dist/mdpreview.html` の 1 ファイルです。インターネットに接続できる開発環境でビルドし、成果物をコミットします。

```bash
npm install        # 依存パッケージ(開発環境のみ)
npm run build      # dist/mdpreview.html を作る
npm test           # ビルド → 単体テスト → E2E(ヘッドレス Chromium + FSA のフェイク)→ 注釈エディタの E2E
```

| 場所 | 内容 |
|---|---|
| `src/app.js` | 全体の配線(開く・保存・変更検知・出力) |
| `src/fs/` | FSA の読み書き(再試行・競合検出)、パス操作、最近使ったフォルダ |
| `src/render/` | md → HTML(markdown-it、@import、見出し id、TOC、アラート、蛍光ペン、マーカー付きテキスト枠)。DOM に依存しない |
| `src/ui/` | ツリー・プレビュー・設定などの画面部品 |
| `src/annotator/` | 画像の注釈エディタと PNG チャンクの読み書き |
| `src/export.js` | HTML 出力 |
| `dev/` | E2E テスト(`harness.mjs`、`annotator-harness.mjs`)と FSA のフェイク(`fake-fs.mjs`) |
| `build.mjs` | esbuild でバンドルし、1 つの HTML にインライン化する |
