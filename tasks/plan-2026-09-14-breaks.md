# 改修計画(2026-09-14): md 上の 1 回の改行をプレビューでも改行にする

状態(2026-09-15): 実装・テスト・目視確認完了(feature/breaks)。進捗は tasks/todo.md で管理する。

## 背景・原因
- md 上で 1 回だけ改行しても、プレビューでは改行されない(前の行とつながる)。2 回改行すると空行のある別段落になり、
  `<br>` を書いたときだけ意図どおりに改行される
- 原因: `src/render/markdown.js` の `createMarkdown()` が markdown-it を `breaks: false` で作っている。
  CommonMark の標準仕様では段落内の 1 回の改行は softbreak(HTML では改行文字 = 空白扱い)になる
- MPE は既定で `breakOnSingleNewLine: true`(1 回の改行 = `<br>`)。MPE の代わりとして使うアプリなので、
  MPE で書いた md が同じ見た目になるのは MPE との互換性の点でも正しい

## 方針
- `breaks: true` にする(markdown-it が softbreak トークンを `<br>\n` として出力する)。**常に有効**にし、設定項目は作らない
  (シンプル第一。MPE の既定と同じ。切り替えが必要になったら後で settings に足す。
  その場合は pipeline.js の mdCache のキーに含める必要がある)
- 変わるのはレンダラの出力だけ。トークン列(softbreak の type)は変わらないため、トークンを見て処理するプラグイン
  (アラート・attrs・TOC・slug・markbox・data-line)には影響しない
- プレビューと HTML 出力はどちらも `renderDocument()` を通るので、両方に同じく反映される

## 事前検証(2026-09-14、/tmp のコピーで `breaks: true` にして確認済み)
- 既存のユニットテスト 194 件はすべて成功(プラグイン単体のテストは各自の `new MarkdownIt()` を使うため影響なし。
  逆に言えば、本番設定での改行の挙動はまだテストされていない)
- `renderDocument()` の出力:

| 入力 | 出力 | 評価 |
|---|---|---|
| `1行目\n2行目` | `<p>1行目<br>\n2行目</p>` | 期待どおり |
| 行末 2 空白 / 行末 `\` の改行 | `<br>` 1 つ(二重にならない) | 問題なし |
| `> [!NOTE]\n> 本文1\n> 本文2` | タイトルの後に `<br>` は入らず、本文だけ `本文1<br>本文2` | 問題なし(マーカー行は inline 解析前に除去される) |
| `:::note info` の本文(複数行) | 本文が `<br>` で改行 | 問題なし |
| `- 項目\n  続き` | `<li>項目<br>続き</li>` | 期待どおり |
| `段落の文\n{.foo}` | `<p class="foo">段落の文</p>`(末尾に `<br>` は残らない) | 問題なし |
| 画像を 2 行に分けて書く | 画像の間に `<br>`(縦に並ぶ) | 期待どおり(MPE と同じ) |
| `==強調==\n次の行` | `<mark>強調</mark><br>次の行` | 問題なし |
| ```` ```mark ```` の枠内 | 変化なし(`<pre>` 内の改行のまま) | 問題なし |
| 脚注の本文(字下げした続きの行) | `<br>` で改行 | 期待どおり |
| 見出しの直後の行 | 変化なし(見出しと段落は別ブロック) | 問題なし |

## 注意点(挙動の変化)
- これまで長い段落を 1 行ごとに折り返して書いていた md は、折り返し位置で改行されるようになる
  (MPE の既定と同じ挙動なので、MPE で見ていた資料はむしろ同じ見た目になる)
- GitHub の .md 表示(breaks なし)とは見た目が変わる。今回の要望どおり MPE 側に合わせる
