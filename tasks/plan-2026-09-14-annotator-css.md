## 1. 吹き出しの文言を修正できない(不具合)

### 原因(再現確認済み)
- `onCanvasMouseDown()` がクリックのたびに `render()` を呼び、`render()` は
  `hitLayer` の当たり判定要素を**全部作り直す**(`clearChildren(hitLayer)`)
- マウスを押した要素が離す前に DOM から外れるため、ブラウザは click / dblclick を
  発火しない。`dom.svg` の `dblclick` リスナーが一度も呼ばれない
- Playwright(Chromium)で確認: 既存の吹き出しをダブルクリック → dblclick 未発火、
  mousedown の対象は mouseup 時点で `isConnected=false`。一方 mousedown の
  `e.detail` は 1 → 2 と正しく数えられている
- 既存の E2E は「作成直後の入力」しか見ておらず、再編集は未検証だった

### 対応
- [ ] ダブルクリックの判定を `dblclick` イベントから `onCanvasMouseDown` の
      `e.detail >= 2` に移す(選択ツールで吹き出しに当たったら `openTextEditor`)。
      `dblclick` リスナーは削除
- [ ] 選択中の吹き出しで Enter / F2 を押しても編集を開けるようにする(操作の発見性)
- [ ] 入力中に吹き出しの枠を追従させる(`input` で shape.text を仮更新して再描画し、
      textarea の幅・高さを合わせる。履歴は確定時に 1 回だけ積む)。
      今は textarea が開いた時の大きさのまま固定で、長い文言に直すと見切れる
- [ ] ついでに直す: 移動していないクリックでも `startMoveDrag` の mouseup で
      履歴が積まれる(元に戻すが空振りする)。移動量 0 なら積まない
- [ ] E2E 追加: ①既存の吹き出しをダブルクリックして文言を修正 ②保存→開き直して修正
      ③Enter で編集開始

対象: src/annotator/annotator.js、dev/annotator-harness.mjs(規模: 小)

## 2. 複数の画像を 1 枚にまとめる(draw.io 風のキャンバス)

### 結論
理想形(自由配置 + 必要な範囲だけ自動で切り出し)で**対応できる**。今の注釈エディタは
SVG で描いて canvas に焼き込む作りなので、「座標系を 1 枚目の画像からキャンバスに
一般化」「画像を複数持てるようにする」の 2 点を足せば実現できる。手動でエリアを
広げる方式はかえって操作が増えるので採らない。

### 仕様
- 画像の追加: ツールバー「画像を追加」(ファイル選択)/ エディタ内で Ctrl+V /
  キャンバスへドロップ。置き場所はドロップ位置、それ以外は今の内容の右隣(24px 空け、上端を揃える)
- 画像の操作(選択ツール): クリックで選択、ドラッグで移動(4px 未満は移動と
  みなさない = うっかりずらし防止)、四隅で拡大縮小(縦横比は固定)、Delete で削除、
  「前面へ / 背面へ」(画像同士の重なり順)。注釈は常に画像より上に描く
- 切り抜き: **画像ごと**に切り抜く(選択中の画像が対象。画像が 1 枚ならその画像)。
  今の切り抜きの操作(外側を暗くする、8 つのハンドル、内側をドラッグで移動)をそのまま
  画像ごとに使う。「切り抜き解除」は選択中の画像を元の大きさに戻す
- 出力範囲: **自動** = 画像(切り抜き後)と注釈すべてを囲む最小の矩形 + 余白(既定 0px)。
  画像がない部分は白で塗る。エディタには出力範囲を点線で表示し、出力サイズの表示もこれに合わせる
  - 画像 1 枚で注釈が画像の内側にあれば、出力は今と同じ
- 表示: 「作業領域を広げる」方式はやめ、SVG を表示枠いっぱいに固定して viewBox を
  カメラ(パン・ズーム)として動かす無限キャンバスにする(draw.io / Figma と同じ方式。
  スクロール補正や領域の再計算が不要になり、枠の外側にも直接描ける)
  - ホイール = 上下にパン、Shift+ホイール = 左右にパン、Ctrl+ホイール = カーソル位置を中心にズーム、
    中ボタンドラッグ = パン、「全体表示」ボタン = 内容全体が収まる倍率(最大 100%)で中央に表示
  - 開いた直後は「全体表示」の状態(今と同じ見え方)
  - 出力範囲は背景色(白)で塗り、点線で囲んで表示する(見たまま出力される)
- 画像が 1 枚だけのときは画像を選択・移動できない(今と同じ操作感。移動しても出力は
  変わらないため)。2 枚以上になったら選択できる。最後の 1 枚は削除できない
- 余白・背景色の設定は作らない(背景は白固定、余白 0。必要になったら追加する)
- 呼び出し側(src/ui/image-edit.js)は変更なし。`openAnnotator({ imageBlob }) → Blob` のまま。
  使い方は「1 枚目を md に貼る → 編集 → エディタ内で 2 枚目以降を貼る/ドロップ」

### データ形式(PNG に埋め込む JSON を version 2 に)
```
{
  version: 2,
  images: [{ id: 'i1', mime, width, height,   // 元画像の大きさ(px)
             x, y, scale,                      // 元画像の左上のキャンバス上の位置と表示倍率
             crop: { x, y, w, h } }],          // 元画像ピクセルでの表示範囲
  shapes: [...],                               // 座標はキャンバス座標(v1 と同じ意味)
  scale,                                       // 出力倍率(今と同じ)
  padding: 0, background: '#ffffff'
}
```
- 元画像のバイト列: 画像ごとに独自チャンク `mdIM`(`id` + NUL + バイト列)。v2 では `mdOR` は書かない
- v1 の読み込み: `images[0] = { x:0, y:0, scale:1, crop: v1.crop }`、shapes はそのまま。
  注釈が切り抜きの外にはみ出していなければ、保存し直しても出力は変わらない
- 古いアプリで v2 の PNG を開いた場合: 焼き込み済みの 1 枚の画像として開く(注釈の
  再編集はできないが壊れない)
- 元画像を全部埋め込むため、スクリーンショットを何枚も重ねるとファイルが大きくなる

### 実装の分担
- shapes.js(DOM なし、node:test で検証): 図形の見た目上の外枠(線幅・矢じり・しっぽ込み)、
  画像の表示矩形、出力範囲の計算
- pngmeta.js: `mdIM` の複数チャンクの読み書き、v1 / v2 の両方を読む
- annotator.js: 状態に `images` を追加、画像レイヤー(画像ごとに入れ子の `<svg viewBox=切り抜き範囲>`
  で切り抜きを表現)、座標変換に作業領域の原点を足す、選択・移動・拡大縮小・重なり順、
  画像ごとの切り抜き、追加(ファイル・貼り付け・ドロップ)、出力(背景を塗る → 画像を順に
  drawImage → 注釈の SVG を重ねる)。履歴には画像の配置だけを入れ、バイト列は id をキーに
  別に持つ(削除しても元に戻せるよう、閉じるまで保持)
- 出力の canvas が大きすぎる場合(一辺 16384px 超など)は、出力倍率を下げるよう案内して止める

### テスト
- node:test: 出力範囲の計算、v1→v2 の変換、`mdIM` の読み書き
- E2E: 2 枚目の追加・移動・拡大縮小・画像ごとの切り抜き・保存と開き直し・出力画素の確認・
  v1 形式の PNG の読み込み
- [ ] 1 → 2 の順で進める(どちらも annotator.js を大きく触るため)

規模: 大(annotator.js に数百行)。src/annotator/ は別セッションが触っていないので並行して着手できる

## 3. 社内資料向けの標準 CSS

### 方針
- src/theme/base.css を社内資料向けに作り直す(既定のテーマを置き換える)。GitHub 風は
  やめる。個別の調整は今までどおり style.css で上書き
- 色・フォントは CSS 変数(`--mdp-accent` など)にまとめ、style.css で変数を上書き
  するだけで会社の色に合わせられるようにする
- 配色は別セッションで作っているアラート(alerts.css)の落ち着いた配色と揃える
  → **アラートの作業が commit された後に着手する**

### 見た目の案
- 文字: メイリオを優先(Windows の社内資料で最もなじみがある)→ BIZ UDPゴシック →
  ヒラギノ角ゴ。16px、行間 1.75。アクセント色は紺(#1f4e79 前後)
- 見出し:
  - h1(資料の表題): 太字、下に紺の太線
  - h2(章): 左に紺の太い縦線 + 薄い紺の帯
  - h3(節): 左に細い縦線
  - h4: 太字 + 紺の文字、h5・h6: 太字(色は控えめ)
  - 見出し番号(1. / 1.1)は自動では付けない。付けたい人向けに style.css の例を README に載せる
- 表:
  - `display: block` をやめて通常の表に戻す(印刷時に見出し行がページごとに繰り返され、
    改ページもきれいになる)。幅は内容に合わせ、長い文字列はセル内で折り返す
  - 見出し行は薄い紺の背景 + 太字、全セルに罫線、下線は少し濃く。1 行おきの色分けはごく薄く
  - `{.full}`(markdown-it-attrs)で幅 100% の表にできるようにする
- その他: 引用・コード・水平線・脚注・定義リスト・kbd・mark を同じ配色で揃える。
  画像は `{.border}` で薄い枠を付けられるようにする(白地のスクリーンショット向け)
- 印刷(PDF 化): A4 の余白、見出しの直後で改ページしない、表の行の途中で改ページしない、
  背景色も印刷する(`print-color-adjust: exact`)

### 確認
- 全要素を含むサンプル md をプレビュー・HTML 出力・PDF(Playwright の page.pdf)で
  スクリーンショットにして目視確認 → ユーザー確認後に commit
- README の style.css の節に CSS 変数の一覧と上書き例を追記

規模: 中(base.css の書き直しと README)
